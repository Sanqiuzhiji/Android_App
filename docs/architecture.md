# 个人工具箱：第一阶段架构

## 阅读顺序

1. `MainActivity`：Activity 只负责启动 Compose。
2. `app/ToolboxApp`：工具箱、每日记录、记录日历、固定清单、备份与恢复五个导航目的地。
3. `feature/dailyrecord/ui`：Screen 展示，ViewModel 接收操作并暴露 StateFlow。
4. `feature/dailyrecord/data/DailyRecordRepository`：功能的数据边界。
5. `LocalDailyRecordRepository`：日期生成和模板生效规则。
6. `data/local` 与 `core/database`：Room 表、查询、事务和数据库版本。
7. `model/CalendarDaySummary`：日期投影与颜色状态的纯逻辑；`ui/CalendarViewModel`：当前月份及月份摘要。
8. `core/preferences/CalendarPreferences`：日期状态文字显示的本地偏好，与任务数据库分离。
9. `feature/backup`：备份文件编解码、数据库快照/恢复、系统文档访问、页面和 ViewModel。

保留一个 app 模块，按功能分包。未来新工具放在 `feature/<工具名>`，首页和导航增加入口即可。
页面不直接访问 DAO；数据库实体不向页面泄漏。`AppContainer` 手动创建依赖；测试使用独立数据库和可控制的时钟。

## 数据与历史规则

- `daily_records` 用 ISO 本地日期作为主键，作为未来日志、心情和附件的关联点。
- `fixed_templates` 的每一行是一版固定模板，生效区间为 `[effectiveFrom, effectiveUntil)`。
- `tasks` 是某一天的任务实例，保存名称快照、类型、完成状态与完成时间。
- `(date, templateId)` 唯一索引保证同日固定任务不重复。临时任务的 templateId 为 null。
- 日期以 `yyyy-MM-dd` 保存，时间戳以 epoch milliseconds 保存。日期来源为设备当前时区。
- 完成统计由当天任务计算，不另存容易失去同步的计数。

访问今天或历史日期时，在 Room 事务内创建每日记录，并插入该日期有效模板中尚未生成的任务。
冲突采用 IGNORE，既有完成状态不会被覆盖。不依赖零点后台进程；未打开过的日期也能按历史模板补齐。
未实际记录完成的任务保持未完成，不能推断用户曾经做过。

新增模板从真实今天生效，立即生成今天的实例。改名和停用从明天生效。
改名关闭旧区间并创建新版本；尚未生效的版本可再次编辑或取消。历史名称和完成状态保持原样。
临时任务仅属于用户选中的日期，可补记历史，也可提前规划未来；支持改名且保留日期和完成状态。
未来固定任务由模板动态投影，`Task.isPreview` 标识预览，禁用勾选并显示说明；不预先写入固定实例。
日期到来后生成真实实例，初始未完成。模板改名/停用立即反映到未来预览，避免残留旧的未来任务。
预览采用 `preview:<date>:<templateId>` 标识；数据库实例使用 UUID，Repository 拒绝向预览标识写入完成状态。
月历仅查询当月 1 日至最后一日的摘要，不批量写入每日记录或任务。`monthGrid` 按星期对齐，邻月日期用空白占位，只保留必要的 4–6 行。
本次未改变 Entity 和数据库版本，现有 v1 数据无需迁移或清理。
输入弹窗固定保存目标日期，避免编辑期间跨午夜导致记录日期改变。

每天首次进入默认今天；跨天回到前台也定位今天。在前台持续浏览历史时不强制跳转。
日期栏支持前后按钮、左滑前一天/右滑后一天、回到今天以及完整月历选择；支持 1900–9999 年的实际日期导航。
每日页面日期栏固定在顶部。任务使用全局未完成/已完成分区，未完成区按固定/临时分组，已完成区跨类型按完成时间从早到晚排列（同一时间按 ID 保持稳定）。
固定清单管理页长按卡片拖动排序，松手后事务内更新模板的 sortOrder 及今天起未完成的固定实例，不修改过去已存实例。未来生成使用模板顺序；今天取消完成的固定任务重新采用模板顺序。未生成历史日期仍按模板顺序投影。
临时任务长按卡片拖动，仅在同一天未完成临时任务之间移动，跳过已完成任务；排序复用现有 sortOrder 字段，无数据库迁移，备份继续保存排序。
`TaskDragReorder` 在列表上识别长按，维护独立的预览顺序；固定清单及未完成临时任务都按预览渲染，跨过邻项中点时立即让位，邻项使用位置动画，拖动项保持与手指的相对位置。按帧检查上下 72dp 边缘区，按靠边程度连续自动滚动（最高 900dp/s）；手指停住时也持续运行。固定/临时/已完成区之间不允许跨区排序，到达可排序区首尾即停止自动滚动。
`TaskDragOverlay` 在列表外绘制同尺寸浮动卡片，列表中保留透明占位；持续滚动时卡片不会因 LazyColumn 回收原条目而消失。浮层清除重复无障碍语义，裁剪在列表范围内。拖动中隐藏添加按钮，避免遮挡下方边缘，松手后一次事务保存目标位置。保留预览直到数据库更新回传，避免旧顺序闪回；取消手势不写数据，保存失败还原顺序并通过现有消息提示。数据源改变或页面离开时结束拖动。不提供上移/下移按钮，无新增依赖。
勾选后保留稳定任务 ID，通过 LazyColumn 位置动画移动到已完成区，显示删除线、颜色变化和完成时间；取消完成清空时间戳并移回未完成区。

## 月历状态优先级

规则集中在 `DailyRecord.calendarSummary`，页面只负责颜色与说明的映射：

| 条件 | 状态 |
| --- | --- |
| 未来有临时任务（包括提前完成的任务） | 蓝色：已安排 |
| 未来无临时任务，只有固定预览或为空 | 灰色：普通 |
| 今天/历史为空 | 灰色：普通 |
| 今天/历史有任务且全部完成 | 绿色：已完成 |
| 今天/历史有未完成任务，包括固定任务 | 橙色：待处理 |

这样解决“只有固定任务”与“有未完成任务”的条件重叠。第一阶段完成良好定义为全部完成，不隐含比例阈值。
今天与选中日期使用边框区分，不覆盖任务状态颜色。日期格默认只显示数字和颜色；“设置 → 显示日期状态文字”可开启状态标签，选择自动保存。无障碍描述始终包含状态。
状态说明仅在日历底部常驻显示，不再提供重复按钮或首次说明弹窗。

## 持久化与扩展

Room 数据库名称 `toolbox.db`，当前版本 1，schema 导出到 `app/schemas` 并纳入版本管理。
发布后每次修改表结构都必须增加版本、编写并测试迁移，不使用 destructive migration。
目前是本地离线存储，无账户、服务器或云同步；卸载/清除应用数据会移除本地数据库。
系统备份使用现有 Android 备份配置；用户也可以使用独立的导出/导入功能保存可控备份。

## 备份与恢复

- `BackupDao` 读取三张表的原始记录，`BackupRepository.snapshot` 在同一事务内读取一致快照。
- 首页每日记录卡片本身不绑定点击，上方内容区进入每日记录，下方整行（含分隔线）进入备份。两个点击区互不嵌套，备份行高度至少 56dp。DAO 仅访问每日记录三张表；未来工具应有自己的表和备份入口，不纳入该恢复事务。
- 新文件标记 `module: daily-record`，拒绝其他模块文件；此前 v1 未标模块的文件仅含每日记录，继续兼容。
- `BackupCodec` 输出带 `format`、`version`、`exportedAt` 的 UTF-8 JSON。备份格式版本独立于 Room 数据库版本。
- 导入校验版本、日期、字段类型、ID 唯一性、模板/日期外键、同日固定任务唯一性及完成时间一致性。大小上限 20 MB，每类最多 100,000 项。
- 导入分为文件预览和明确确认。确认后在一个事务内先清理子表，再替换记录及模板、插入任务；失败整体回滚。不做隐式合并，不清库升级数据库。
- `BackupFiles` 使用 ContentResolver 读写用户在系统选择器中选定的 URI。导出保留最近文件的可持续权限和名称/位置元数据；导入读取后无需保留权限。
- 原始内容 URI 供定位/分享使用。位置说明仅在识别到标准本机目录时展示路径，其余情况不伪造绝对路径。
- 页面能复制文件名并启动系统选择器定位，也能通过 Android 分享面板分享。定位选择器的返回结果不会触发导入。
- 页面只接收预览计数，实际待恢复快照由 ViewModel 持有；旋转屏幕保留，进程终止后须重新选择文件，不自动重放恢复操作。
- 本次新增 DAO，不更改任何 Entity、数据库表结构或 v1 schema。

未来日志和心情可关联每日记录；照片建议建立附件表保存 URI，避免把二进制图片塞进任务表。
工具增多或业务出现复用时再抽取模块或 UseCase，当前不添加空壳抽象层。

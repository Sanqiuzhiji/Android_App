# V2.0 任务提醒

入口：个人工具箱 → 任务提醒。首页卡片与每日记录共用标题、三条说明及底部备份入口的布局，不显示版本号。提醒点和常用地点独立保存在应用私有存储中，通过任务提醒卡片底部的“备份与恢复”导出和恢复；每日记录仍单独备份。

## 使用

1. 开启通知、精确定位；Android 12 及以上点击“允许准时提醒”。拒绝精确闹钟权限时使用可能延迟的系统闹钟。
2. 在常用地点中添加学校、宿舍等，可获取当前位置、联网地图选点，或者填写 WGS84 经纬度。地址搜索放在地图页面内：搜索成都等大概位置，选择结果移动视野，拖动、缩放地图后点击具体地点，最后按“使用此位置”。搜索结果不会直接保存为地点。地图使用 OpenStreetMap，搜索使用手机系统 Geocoder。高德 GCJ-02、百度 BD-09 坐标不能直接填写。
3. 创建提醒点，选日期，再选当天未完成的固定或临时任务。未来固定任务通过模板 ID 与日期关联，不依赖预览任务 ID。
4. 地址模式只设置关联任务的日期，不设置时刻；时间模式和地址＋时间模式必须设置日期与具体时刻，不再提供“仅日期”选项，保留系统日历与时钟选择器。时间模式可提前 0–1440 分钟，页面显示首次提醒时间。地址模式不限制时刻，日期仅用于任务关联；创建、编辑保存、恢复时已在地点内不会立即触发，需先离开，再进入。定位不确定或短暂丢失不会被当作离开，边界外还需留出定位精度余量，以减少定位漂移造成重复触发。旧版仅日期数据仍可读取，编辑保存时需补全具体时间。
5. 组合模式的有效区间为“设定时刻减提前分钟”至“设定时刻加时刻后有效分钟”，编辑页和提醒卡片展示实际起止日期、时间。例如设定 12:00、时刻后有效 60 分钟：提前 0 分钟是 12:00–13:00，提前 10 分钟是 11:50–13:00。提前只改变开始时间，截止时间仍以设定时刻计算。进入区间时已经在地点内也能提醒。
6. 响铃、震动至少开启一项。使用系统通知提示音和震动，受系统音量、勿扰及通知渠道设置控制，不是持续响铃的闹钟。
7. 通知可跳转到关联日期的每日记录。“关联任务”和“提醒方式”使用独立卡片，响铃、震动位于单独底色区域。每次投递前检查任务；应用运行时也监听每日记录变化，完成或删除任务后停止后续提醒并清除该提醒的通知。
8. 地址模式每次确认离开后重新进入提醒一次，持续停留不会重复响。两个含时间的模式可设置重复间隔，默认 10 分钟，可设 1–1440 分钟；时间模式从首次提醒时间起持续到任务完成或暂停，组合模式仅在有效区间内且处于地点范围内重复。每次成功提醒后重新计算间隔，不集中补发错过的次数。
9. 提醒后仍可暂停，暂停后直接点“恢复”，无需编辑保存。已提醒且仍启用的卡片还有“恢复下次提醒”：地址模式重置为等待离开后再进入，时间及组合模式从恢复时刻重新等待一个间隔（尚未到开始时间时仍等待开始时间）。自动完成或缺失的任务不会因恢复操作而绕过任务检查。

## 后台行为

- 时间提醒通过 AlarmManager 安排，重启、时区/时钟变化、应用更新及准时提醒授权后重新安排。时间模式不再受原一小时补发期限限制；组合模式仍受设定的截止时间限制。锁屏和省电机制可能使实际间隔延迟。
- 地点提醒使用前台定位服务，并显示常驻运行通知；约每 15 秒请求定位。范围默认为 200 米，可设 50–10000 米。只使用两分钟内且精度不差于半径的位置；室内、无定位信号时可能延迟，无法可靠区分楼层。
- 手机重启后会发通知提示打开应用恢复地点监测。全部地址提醒暂停、删除、任务完成或组合区间过期时停止服务；地址提醒触发一次后仍需继续监测离开与再次进入。
- 系统强制停止应用、关闭定位、关闭通知或厂商省电限制可能阻止提醒；恢复后打开应用。应用设置入口供检查权限和电池后台运行设置。

## 建议真机验证

- 首页两张卡片布局一致，任务提醒底部可进入独立备份页面。
- 搜索成都仅移动地图视野，必须点选具体位置后才能保存；断网或底图失败时有提示和重试入口。
- 导出提醒备份后修改地点及提醒，再导入并确认替换；核对地点、半径、任务关联和已提醒状态。尝试导入每日记录备份，应拒绝且不修改数据。

- 创建两个常用地点，重复选择；修改默认半径，检查已有提醒保留独立半径；引用中的地点不可删除。
- 时间设为几分钟后，切到其他应用并锁屏，验证响铃、仅震动，以及提前提醒。
- 地址模式日期设为未来，进入地点范围仍应触发；留在范围内不重复提醒。
- 组合模式分别验证先到地点后到时间、先到时间后进入地点，以及超过有效期不提醒。
- 对关联任务完成、删除、固定任务未来预览转正式记录、通知打开日期进行验证。
- 验证拒绝定位/通知/准时提醒权限时的提示，以及重启后的时间安排和地点恢复提示。
- 在宿舍创建地址提醒应不马上响；离开再进入会响，待在里面不重复，未完成时再次离开再进入还会响。
- 提醒后点击暂停、恢复或“恢复下次提醒”，检查无需编辑保存；在每日记录勾选完成后，通知消失，后续进入或定时不再提醒。
- 设 12:00、提前 10 分钟、间隔 10 分钟，未完成时应从 11:50 起在 12:00、12:10 等继续；组合模式需同时在地点内，且不能超过截止时刻。

Android 平台依据：[前台定位服务](https://developer.android.com/develop/background-work/services/fgs/service-types#location)、[系统闹钟](https://developer.android.com/develop/background-work/services/alarms)。

## 提醒独立备份

JSON 标识为 `module: task-reminders`、`version: 2`，兼容旧版 v1，包含全部提醒点与常用地点，含任务关联 ID、日期、范围、提醒方式、重复间隔、上次提醒时间及停止原因。旧数据默认重复间隔为 10 分钟；“已提醒”是历史信息，不再意味着永久停止。恢复时重置地点进入状态，避免沿用另一设备的离开状态造成误提醒。先预览数量，再明确确认替换；不会写入每日记录。导入会校验坐标、日期、范围、重复 ID 和地点引用，校验失败时不更改数据；两个列表通过一次持久化提交替换，并与提醒投递互斥。

跨设备时先恢复每日记录，再恢复提醒；无法找到关联任务或任务已经完成时会暂停提醒。应用权限、后台定位服务和系统通知设置不能通过 JSON 备份恢复，恢复后进入任务提醒页面检查权限并恢复监测。

## 地图空白的排查与本次修改

原页面在线下载 unpkg 的 Leaflet 脚本和样式，再向 OpenStreetMap 请求底图，任何一步不可用都可能导致空白，且原界面缺少失败提示。本次开发环境探测中，通用请求收到 HTTP 200 但带 `x-blocked: Access denied` 的图片响应；使用明确应用标识和来源后同一图片地址返回正常地图。该结果不能代替用户手机网络上的验证。

现已将 Leaflet 1.9.4 脚本、样式与许可证随 APK 打包，通过受限 HTTPS 资产路径加载；地图请求增加应用标识，使用浏览器默认缓存，并保留地图署名。新页面提供超时、加载失败提示、重试和加载区域检查，底图仍需手机能访问 OpenStreetMap。没有引入未经授权的高德或百度瓦片接口。

若用户网络仍无法访问底图，国内地图接入建议使用正式高德 JS API：在高德开放平台创建应用，添加“Web 端（JS API）”Key，取得对应安全密钥 jscode。当前版本未接入高德，不能把 Key 直接填进当前页面；后续接入还需正确处理高德坐标与当前 WGS84 定位的转换。公开发布前按高德文档配置安全代理。

参考：[Leaflet 下载与本地部署](https://leafletjs.com/download.html)、[OpenStreetMap 底图使用要求](https://operations.osmfoundation.org/policies/tiles/)、[高德 JS API 准备工作](https://lbs.amap.com/api/javascript-api-v2/prerequisites)。
